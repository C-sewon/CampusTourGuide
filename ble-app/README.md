# odp_team1 - 캠퍼스 센서 수집 앱

캠퍼스에 설치된 고정 BLE 센서(`opensrc1` ~ `opensrc5`)의 온도/습도/AQI/TVOC/eCO2 값을 스캔하여,
연구실 서버의 센서 데이터 전송 API(연구실 센서 공용 API 명세서 v4의 2번 API)로 업로드하는 안드로이드 앱입니다.
여기로 올린 값은 연구실 최신값 API(1번)에 반영되고, 우리 서버가 그 값을 가져갑니다. (#26)

## 1. 사전 준비

- 안드로이드 기기 (BLE 지원)
- 블루투스 켜짐
- 위치 서비스 켜짐 (안드로이드는 BLE 스캔에 위치 권한과 위치 서비스를 요구합니다. 업로드에는 폰 위치를 쓰지 않습니다)
- 인터넷 연결 (연구실 서버 업로드용)

## 2. 빌드 및 설치

Android Studio에서 프로젝트를 열고 Gradle Sync 후 실행하거나, 터미널에서:

```bash
./gradlew assembleDebug
```

생성된 APK(`app/build/outputs/apk/debug/`)를 기기에 설치합니다.

## 3. 최초 실행 시 권한 허용

앱 실행 시 아래 권한 요청 다이얼로그가 뜹니다. **모두 허용**해야 정상 동작합니다.

- 블루투스 스캔 / 연결 (Android 12 이상)
- 위치(정밀 위치, `ACCESS_FINE_LOCATION`)

권한을 거부하면 "블루투스/위치 권한이 없으면 스캔할 수 없습니다" 토스트가 뜨고 스캔이 시작되지 않습니다.
설정 > 앱 > 권한에서 나중에 허용해도 앱을 재실행하면 정상 동작합니다.

## 4. 화면 구성 및 사용법

| 버튼 | 동작 |
|---|---|
| 스캔 시작 | BLE 스캔을 시작합니다. 주변 광고를 모두 수신하되, 코드 내부에서 `opensrc1`~`opensrc5` 기기명만 걸러냅니다. |
| 스캔 중지 | BLE 스캔을 멈춥니다. |
| 저장 | 그동안 수신된 모든 센서값을 기기 내부 CSV(`ble_data.csv`)에 저장하고 버퍼를 비웁니다. |
| 전송 | 가장 마지막으로 수신한 센서 1건을 서버로 보냅니다. 이미 보낸 측정 시각이면 `[중복 생략]`으로 표시하고 보내지 않습니다. |

### 동작 순서 (정상 케이스)

1. 앱 실행 → 권한 허용
2. "스캔 시작" 터치
3. 캠퍼스 센서(`opensrc1`~`opensrc5`) 근처에 있으면 로그 창에 다음이 순서대로 출력됨:
   - `[수신] 이름: opensrcN, MAC: ..., RSSI: ...` + 파싱된 센서값
   - `[전송 시작] opensrcN (RSSI ...)`
   - `[서버 응답: 정상] opensrcN(sensor NN) RSSI ... - success - Data received (id ...)`
4. 같은 센서는 **10초에 한 번씩만** 자동 업로드됩니다(연속 중복 전송 방지).
5. 필요 시 "저장" 버튼으로 CSV 백업, "전송" 버튼으로 마지막 값 수동 전송.

### 업로드 형식 (연구실 2번 API)

```
GET http://203.255.81.72:10021/sensor/sensing/?mac=...&sensor=sensor 07&sender=...&mode=mobile&temp=21.37&co2=620&time=1790600000&rssi=-58
```

| 파라미터 | 값 |
|---|---|
| `mac` | 폰에서 보이는 센서 MAC |
| `sensor` | 연구실 이름. opensrc1~5 → sensor 07, 15, 31, 32, 33 (명세서 부록 B, `Sensors.java`) |
| `sender` | 스마트폰 ID (`ANDROID_ID`) |
| `mode` | `mobile` |
| `temp` | 온도 ℃ (패킷의 × 100 값을 100으로 나눔) |
| `co2` | eCO2 ppm |
| `time` | 패킷의 측정 시각 (Unix 초) |
| `rssi` | 수신 신호 세기 (dBm) |

- 습도, AQI, TVOC는 2번 API에 받는 칸이 없어서 보내지 않습니다. (CSV 저장에는 남습니다)
- 경로 끝의 `/`(`sensing/`)는 있어야 하고, 마지막 값 뒤에는 `/`를 붙이지 않습니다. `LabSensingApiTest`가 확인합니다.
- 인증 없이 연구실 운영 데이터에 바로 반영되므로, 실제 센서에서 받은 값만 올립니다.
- **센서 오류값은 앱에서 거르고 올리지 않습니다.** 2번 API에는 습도 칸이 없어서 서버가 걸러낼 수 없기 때문입니다. (`ReadingCheck`)
  - 온도와 습도가 모두 0.0인 값 (센서 3, 4의 증상). 온도만 0.0이면 겨울 값이라 올립니다.
  - 온도가 -20~45℃ 밖인 값 (예: 73℃). 우리 서버의 오류 범위와 같습니다.

## 5. 로그 메시지 안내

| 로그 | 의미 |
|---|---|
| `[무효] RSSI 0` | RSSI 값이 0으로 수신됨 (비정상 신호로 간주, 전송 안 함) |
| `[서버 응답: 정상] ... - success ...` | 연구실 서버가 값을 정상적으로 받음 |
| `[재전송 대기] N건, M초 뒤 다시 시도` | 네트워크 오류나 서버 오류로 실패해서 큐에 보관함. 자동으로 다시 보냄 (10번 참고) |
| `[전송 포기] ... HTTP 400 ...` | 서버가 요청 자체를 거절함(파라미터 누락·형식 오류 등, 다시 보내도 실패). 큐에서 버림 |
| `[알림] 예전 형식의 재전송 대기 값을 정리했습니다` | 업로드 API를 바꾸기 전 형식으로 남아 있던 큐 파일(`upload_queue.json`)을 지움. 업데이트 후 처음 한 번만 나옴 |
| `[중복 생략] ...` | 같은 센서의 같은 측정 시각을 이미 보내서 다시 보내지 않음 |
| `[전송 안 함] 센서 오류값(온도와 습도가 모두 0.0) ...` | 센서 오류값이라 올리지 않음 (센서 3, 4) |
| `[전송 안 함] 온도가 오류 범위(-20~45℃) 밖 ...` | 고장 값이라 올리지 않음 |
| `[재전송 대기] ... 응답 처리 오류 ...` | 서버 응답을 처리하다 예상 밖의 오류가 남. 큐가 멈추지 않도록 다시 보내기로 처리함 |

## 6. 문제 해결(트러블슈팅)

- **로그에 아무것도 안 뜬다**: 센서가 광고하는 실제 기기명이 `opensrc1`~`opensrc5`와 정확히 일치하는지 확인하세요(대소문자/공백 포함 한 글자라도 다르면 무시됩니다). `MainActivity.java`의 `TARGET_NAMES` 참고.
- **스캔을 눌러도 아무 기기도 잡히지 않는다**: 위치 권한이 허용되어 있는지, 위치 서비스가 켜져 있는지 확인하세요. 안드로이드는 위치가 꺼져 있으면 BLE 스캔 결과를 주지 않을 수 있습니다.
- **블루투스가 꺼져 있다는 토스트**: 기기 블루투스를 켜고 "스캔 시작"을 다시 누르세요.

## 7. 설정값 (MainActivity.java 상단)

| 상수 | 설명 |
|---|---|
| `TARGET_NAMES` | 수집 대상 센서 기기명 목록 |
| `UPLOAD_INTERVAL_MS` | 센서별 업로드 최소 간격(기본 10초) |
| `AUTO_UPLOAD` | `false`로 바꾸면 자동 업로드를 끄고 수동 전송만 사용 |

## 8. 도착 판정

스캔 중 센서 근처에 도착하거나 떠나면 로그 창에 `[도착] 센서 N (opensrcN) - 위치`, `[떠남] 센서 N`이 표시됩니다.
규칙은 CampusTourGuide #2 에서 합의한 내용입니다.

- 센서별로 최근 10초 동안 받은 신호 세기(RSSI)의 평균을 사용
- 여러 센서가 잡히면 평균이 가장 센 센서 하나만 선택
- 평균 -70 dBm 이상이면 도착, -80 dBm 아래로 떨어지면 떠남 (경계에서 도착과 떠남이 번갈아 뜨지 않도록 기준을 다르게 둠)
- 최근 값이 3개 이상 있어야 도착으로 처리 (한 번 튄 값 무시)

| 파일 | 내용 |
|---|---|
| `Sensors.java` | 센서 5대의 번호, BLE 이름, 연구실 이름, MAC, 위치 (CampusTourGuide README의 센서 표와 같음) |
| `ArrivalDetector.java` | 도착 판정 로직. Android 기능을 쓰지 않아 다른 앱 프로젝트로 그대로 옮길 수 있음 |
| `ArrivalDetectorTest.java` | 도착 판정 단위 테스트 (`./gradlew testDebugUnitTest`) |

## 9. 주의: 프로젝트 경로에 한글이 있으면 빌드 실패

Android 빌드 도구는 경로에 한글 등 ASCII가 아닌 문자가 있으면 실패합니다. (예: `C:\Users\...\문서\...`)
이 저장소를 `C:\Users\<사용자>\AndroidStudioProjects\CampusTourGuide`처럼 영문 경로에 받아서 `ble-app` 폴더를 Android Studio로 여세요.

## 10. 재전송 큐

업로드에 실패한 값을 버리지 않고 모아 두었다가 다시 보냅니다. 캠퍼스를 걷다가 네트워크가 잠깐 끊겨도 값이 사라지지 않습니다.

- 모든 업로드는 큐를 거칩니다. 네트워크가 정상이면 바로 보내고, 실패하면 큐에 남깁니다.
- 같은 센서의 같은 측정 시각은 한 번만 보냅니다. 센서는 약 10초마다 값을 바꾸므로, 그 사이에 여러 번 스캔된 같은 값은 로그에 `[중복 생략]`으로 표시하고 보내지 않습니다.
- 한 번에 한 건씩, 들어온 순서대로 보냅니다.
- 결과에 따라 이렇게 처리합니다.

| 결과 | 처리 |
|---|---|
| 성공 (HTTP 2xx) | 큐에서 뺌 |
| 서버가 요청을 거절 (HTTP 4xx, 408·429 제외) | 다시 보내도 실패하므로 버림 |
| 네트워크 오류, 서버 오류 (5xx), 408, 429 | 큐에 남기고 다시 보냄 |

- 재시도 간격은 5초에서 시작해 실패할 때마다 두 배로 늘리고 최대 5분입니다. 한 번 성공하면 다시 5초로 돌아갑니다.
- 큐는 최대 500건입니다. 넘으면 가장 오래된 값부터 버립니다.
- 큐는 앱 내부 저장소의 `upload_queue_v2.json`에 저장되어, 앱을 껐다 켜도 남습니다. 다시 켜면 로그에 `[재전송 대기] 지난번에 못 보낸 값 N건`이 표시됩니다.

| 파일 | 내용 |
|---|---|
| `UploadQueue.java` | 재전송 큐. Android 기능을 쓰지 않아 다른 앱 프로젝트로 그대로 옮길 수 있음 |
| `UploadQueueTest.java` | 재전송 큐 단위 테스트 (`./gradlew testDebugUnitTest`) |
